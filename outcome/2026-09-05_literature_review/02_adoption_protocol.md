## E0：最優先は既存の小規模統合参照比較

RAINの8/12/24便の既存計画を、既存承認手続き後に使う。新しい文献の設定で置き換えない。

評価名は「Phase 3整合小規模解とscalar統合参照解の同一尺度による評価額差」。両者の目的の扱いに差があるため、純粋な分解誤差ではない。参照側で必要な証明が得られなければ、厳密解との差とは書かない。小規模の差を264便に外挿しない。

## E1：同じ配車で、充電を工夫する価値はあるか

反証可能な問い：同じ物理配車・設備・PV・料金・SOC条件で、充電最適化は決定論的な単純充電より実行時費用を下げるか。改善なし・単純方式の方が安い・片方が不成立、も残す。

設計上の仮名B00/B01を使う。既存M0/M1の別名にはしない。

| 固定/変更 | B00：単純充電 | B01：充電最適化 |
| --- | --- | --- |
| 担当便と車両、帰庫時刻 | 事前固定した同一配車 | 左と完全一致 |
| 充電 | 決定論的ルール | 最適化 |
| PV・設備・料金・車両初期/終端条件 | 同一 | 同一 |
| BESSと系統の制御規則 | 共通の事前定義 | 左と一致させる |
| 情報利用時刻・評価器 | 同一 | 同一 |

実装前に決める残件：既定配車の出典、充電要求発生条件、帰庫同時刻の優先順、充電目標SOC、出発時打切り、系統/充電器出力制限への割当、BESS方策。これらを結果を見て都合よく選ばない。先着順という名称だけではbaselineは定義できない。

現行Stage 2が充電とBESSを共同で変更するなら、B01は「充電だけ」ではなく「充電＋エネルギー制御の共同最適化」と命名する。BESSを共通化できる既存インターフェースがあると推測しない。実装前に経路と制約を確認する。

選択済みの良い配車に条件付けた比較なら、その選択バイアスを明記する。候補選択を含む方式全体の優位性は、別の事前定義した配車方式との比較を必要とする。B10/B11への拡張は初回比較の後。

主指標は同じ実行期間の費用差 `C(B00) - C(B01)`（JPY）。両方の全便充足・物理・会計・終端条件が成立したペアのみ費用比較できる。差額の比率は分母と共通固定費を明示する。費用がゼロ/負なら無理に改善率を出さず差額を使う。片方の失敗は除外して隠さず別件数で示す。

## E2：予測が外れたとき、作った計画はどこから壊れるか

最初は確率を仮定しない感度試験にする。候補条件は名目、電費+10%、PV低下、両方。PV低下幅は実験前の承認項目で、+10%等をこの地域の実測誤差分布と呼ばない。実行開始時点で条件表・予算が未決なら開始しない。

二つの問いを混ぜない。

1. **固定計画のストレス**：配車・充電・BESS行動を固定する。消費増加やPV減少によるSOC/電力収支違反を記録し、架空の系統補填や充電追加はしない。
2. **再計画能力**：利用可能になった情報だけで再最適化する。過去行動固定、制御可能な機器、更新間隔、計算上限を宣言する。こちらは別実験であり、固定計画の成功数へ足さない。

全方策へ同じストレスを与える。実日付データが揃えば、予測の学習/選択日と評価日を時間順で分ける。交通・電費は可能なら同じ走行記録の組を保持し、相関を消した独立乱数だけで十分としない。二つの実日付を何度solverで解き直しても、実際の天候サンプルが増えたことにはならない。

結果は便充足、遅延/接続違反、最低/終端SOC、電力収支、失敗時刻、費用を報告する。実行不能計画の費用を有効計画と同列に順位付けしない。ストレスでの失敗は名目計画の頑健性の限界であり、それだけで元の名目実行の正当性を否定するものではない。

Kangらの緊急充電や、探索法の解修復をそのまま持ち込まない。本リポジトリのfallback・post-solve repair禁止を維持する。

## E3：PV/BESSや充電器の効果を分ける

- 設備価値を見る比較ではPV/BESS等の変更を一つずつ宣言し、それ以外を固定する。これはICE表現A/Bや充電方策比較とは別系列。
- 「現在の設備で電気代がどう変わるか」と「その設備を買う価値があるか」を分離する。後者には設備費・寿命・割引/年価換算等が必要で、現在の運用費用差だけでは答えられない。
- 電源フローは営業所/時刻単位の正本と、按分した車両別推定を区別する。新しい源別帰属を作らない。
- 充電器が空いている平均時間だけで削減台数を決めない。充電可能時間と必要エネルギーが集中する時刻を調べる。
- 待ち時間には充電需要が発生した時刻と実充電開始が必要。現行のpower-active port-hours比をChiuらの全基同時利用確率と同一指標として比較しない。

先に得た「PV抑制と無充電が同時に起きた」は記述的所見。新しいアブレーションを行うまでは原因別の抑制割合と呼ばない。

## E4：Rollingの価値を測る前の条件表

中野2025の比較では更新だけでなく2日horizon・予測・終端条件も変わる。本研究で更新の寄与だけを問うなら、それ以外を合わせる。

最低限、全方式について `planning_horizon / execution_interval / forecast_cutoff / terminal_SOC / exogenous_realization / recourse_allowed` を実際の設定から表にする。これらは報告欄の名称であり、新しいCLI引数ではない。

完全情報参照は未来情報を使った比較用参照として明示する。実装が将来を知って運用できたように書かない。現行の24時間・60分Rolling・15分内部刻みとSOC制約は、このレビューを理由に変えない。

## 全実験で維持する規律

既存scenario ID、WEEKDAY反実仮想、Prepareが確定した車両集合を維持。固定35/26台の再導入なし。実験開始前にcleanな凍結SHA、ハッシュ、実効solver controls、時間上限、停止条件、署名を確定する。同一系列の途中でコードを変えない。

runtimeの反復、探索seedの反復、実日付/誤差の反復は別のサンプル軸。少数の対応ケースに独立標本の検定を機械的に適用しない。まず全ペアの差と中央値/IQRを示す。検定が必要なら実験単位と多重比較を先に決める。

GitHub Actions、課金機能、クラウド実験は使わない。今回の採用は報告と設計までで、数値モデルの制約緩和や新規実行を許可していない。
