## 図表の根拠・集計方法

- 実験SHAは `bb0c0050883a91dd86a9e8813ae88d4b6d8c361d`。今回のHEADの実験結果ではありません。
- `load_and_validate_bundle`で凍結bundleを確認し、各毎時結果の**実行した先頭60分だけ**を接続しました。
- 営業所の96枠フローを保存 `executed_energy_flow_hash` と照合し、最終台帳の日合計に一致させています。
- BEV SOCは**枠開始値**、BESS SOCは**枠終端値**です。BEVの24時値には最終stepのterminal metadataを使います。
- 充電電力はsolver出力の同一車両・充電器・時刻を集約。車両別の比例電源配分をsolver-nativeと呼びません。
- 車両例は条件ごとに最大充電器入力の1台。高PV `a645e188-64a8-4244-9882-49f00eeb8a62`、低PV `3e38e74f-191a-4b72-8061-59f0020151e3`。代表平均・同一車両比較ではありません。
- 図のデータはExcel互換のため小数6桁に丸めています。完全精度と出典ハッシュは [review_data.json](analysis/review_data.json) に保持。
- 費用は最終 `executed_day_accounting.json` の評価額。燃料の未補給在庫評価を含み、現金支払額や総保有費用ではありません。表示は0.01円、原精度の照合許容は1e-6円。
- 約381秒の `solve_time_seconds` はStage 1＋採用候補Stage 2の範囲。全22候補・前後処理を含むwall timeではありません。
