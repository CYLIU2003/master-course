# 太陽光が多い選択週で費用が高い理由と最適性の診断

2026-09-21のユーザー質問への確認。固定 `68f2f4e5` の保存済み12週だけを読み、計算・監査原本と送信済み報告は保持した。新たな求解・シミュレーション・モデル修正・メール送信は行っていない。

結論: ソルバーは動いているが、週間総費用を十分小さくできたとは認められない。運転成立・会計一致・BESS週末復元の通過は維持する。一方、計画上の将来BESS利用と実行上の予備残量に不整合があり、配車の探索改善も確認できない。太陽光そのものが費用を増やすという結論には使わない。

## 確認した費用差

| 指標 | 1月6日開始週 | 5月12日開始週 |
|---|---:|---:|
| 実績PV発電量［kWh］ | 15,703.5375 | 26,623.9125 |
| 確定週間総費用［円］ | 5,468,389.866126 | 7,703,260.918491 |
| 車両使用費［円］ | 4,100,000 | 4,120,000 |
| 購入電力料金［円］ | 289,260.203070 | 368,766.388016 |
| 契約超過費［円］ | 1,037,426.301535 | 3,171,321.085261 |
| PV抑制率 | 28.94% | 69.44% |

総費用差 `2,234,871.052366円` のうち `2,133,894.783725円`（95.48%）が契約超過費の増加。超過費は実電力契約を確認した料金ではなく、今回の宣言条件 `500円/kWh × Σ max(区間購入量−50 kWh, 0)`。15分当たり50 kWhが200 kWに相当する。最大ピークだけに掛ける料金ではない。一般の電気料金制度として解釈しない。

各月は日付・PV曲線・季節予測が異なり、配車も固定した対比較ではない。週の日射総量が多くても、バスが充電できる時間と一致するとは限らない。5月はPVの69.44%を抑制しており、PVの多さがそのまま買電削減に結びついていない。

## 計画と実行に残っていた不整合

`src/optimization/milp/pv_execution_reserve.py` は `committed_pv_execution_slots` で直近1時間の4区間だけを選び、その区間に3,000 kWhの保護を追加する。前日計画ではこの制約は無効で、rollingでも1時間より先の予測軌道には物理下限1,200 kWhが残る。`reoptimizer.py` が固定する各窓の終端3,000 kWhは、途中の将来軌道まで保護する条件ではない。

実際の5月hour 012では、実行開始3,000 kWh、保護区間48〜51に対し、予測の残り区間は最低1,395.87465 kWh、3,000 kWhを割る区間が32個ある。この24時間計画のStage 2目的値は丸め誤差内で0円。前日計画もBESSを1,200 kWhまで使い、予測上は週間買電・超過とも0だった。一方、実運用では毎時3,000 kWhを守り、5月の週間買電12,292.213 kWh・超過費317.13万円を生じた。

これは、先では利用できると見込んだ蓄電量が、その時間に来ると実行規則により使えなくなる構造である。後の安価な供給を見込んだ計画を毎時作り直し、必要な充電に高価な買電が発生し得る。これが費用全体の何円に相当するかは、条件を揃えた修正比較をしなければ確定できない。

## 直前の予測外れだけでは説明できない

全2,016回の保存予測から、実際に指令した先頭4区間だけを抜き出し、同じ区間の実績再生と比較した。24時間先までの目的値を重複加算していない。

| 超過費［円］ | 各1時間指令の予測上合計 | 実績再生による合計 |
|---|---:|---:|
| 1月 | 1,038,193.176535 | 1,037,426.301535 |
| 5月 | 3,116,640.241182 | 3,171,321.085261 |
| 7月 | 2,994,166.119092 | 2,976,887.494092 |

5月の差は54,680.844079円で、約312万円の超過は直前計画にも既に含まれていた。実PVが足りず突然生じた追加費用だけが主因だとは言えない。ただし各時点の観測BESS残量には過去の予測誤差が蓄積しており、この比較は週間全体の予測誤差の因果効果を分離したものではない。

現在のPV実行器は、バスの充電指令とBESS放電を固定し、BESSへのPV充電も発行済み指令量までに制限する。5月hour 012 slot 48はBESSが3,000 kWhで物理上限4,800 kWhに余裕があっても、PV充電指令0のため実績PV75.4375 kWhを抑制していた。余裕のある各区間を足し上げた量は、そのまま週間の実現可能な削減量とは扱わない。追加充電を許す変更には、将来の上限SOC・充放電同時禁止・終端復元まで整合する別の制御設計が必要。

## 最適化が到達した範囲

- 配車のStage 1は12週すべて120秒枠で時間切れ。保存された最初の実行可能解と最終解の目的値は全12週で一致し、最初の候補からの目的値改善は確認できない。根ノードLP境界は未記録、MIP進捗callbackの初回時刻も未記録。探索が十分進んだとは主張しない。
- Stage 1認証gapは84.52〜85.15%。これは代理目的と弱い下界に対する隔たりであり、実週間総費用が85%割高という意味ではない。
- 充電・PV・BESSのStage 2は固定された配車と予測・窓条件の問題。前日12件は `optimal`。rolling 2,016件中2,013件は `optimal`、3件は実行可能解を伴う `time_limit`。時間切れは3月・6月・11月各1回、最大gapはそれぞれ18.17%、16.45%、13.98%。
- 宣言MIP gapは10%。Gurobiの `optimal` は指定許容差内の意味であり、厳密なgapゼロや実運用全体の最適性とは一致しない。[公式説明](https://docs.gurobi.com/projects/optimizer/en/current/concepts/modeling/objectives.html)。また、毎時の予測目的は実週間会計と別の量である。

## 修正の優先順位と未実行の検証

1. 前日計画・rollingの将来区間・発行指令で、同じBESS運用制約を予測できるようにする。単に現在の3,000 kWh保護を外して旧停止を戻すことはしない。将来の各1時間区間の開始SOCと指令放電による予備残量条件も整合させる。
2. その条件でBEVの前日境界・充電時刻を再評価し、高額な買電を前提にしてしまう計画を点検する。BESS窓末の固定値と余剰PV充電の扱いは、週間復元・実行可能性を保って設計する。
3. 配車の初期解・探索改善を測り、予測上の最適化と実績での費用・超過を併記する。PVだけを変えた固定条件比較と、予測誤差のない整合性確認を区別して行う。

同じ時刻・需要・設備・制約・目的を固定し、各時刻のPVを増やし、余剰を無償で抑制できる最小化問題なら、元の解も実行可能なので数学上の最小費用は悪化しない。現在の月別結果はそのような制御された単調性の検証ではない。季節効果・PV単独の効果の根拠として使う前に、上記の不整合を解消して別版で比較する必要がある。
