この診断は、保存済みの東急バスODPT渋24時刻表（2026-09-01取得）6パターン、平日224便、土曜188便、日祝170便を使う。選んだ運行日は2025-05-12で、2026年公開ダイヤを2025年の気象条件に当てる反実仮想である。2025年実運行の再現ではない。各便の距離は公式停留所座標間の地理的代理距離で、実道路距離ではない。公式サイトの全便画面照合は未完了で、正式研究入力の承認は別に必要である。

車両、充電器、料金、PV/BESS、SOC、回送・折返し条件は、保存済み渋21〜23の親シナリオ `771d115b-75b0-49f7-a7f0-25f259a2cd21` から複製して継承する。渋24の路線・便・停留所・停留所時刻のみ、ハッシュ検証済みの公式取得候補で明示的に置き換える。平日1日だけを評価するため、計画期間は24時間、BEV/BESSの終端判定もその日の終わりになる。この条件は従来の7日間結果とは異なる。求解はライセンス非依存ALNSとし、従来のGurobi二段階法の解品質・最適性と同一視しない。

## 配置・実行

追加4台は本人確認済みのTailnet IP、ノードID、SSH host keyを照合し、既存の初期設定ZIPを送付した。2026-09-23に4台すべてでPython 3.14.7、依存ライブラリ、Gitの導入を検証し、旧固定版 `2e2333b3d27aa49f62a16e5387a1df39897ce26f` のコード・runtime・datasetハッシュ照合を通過した。これは追加4台の環境・配置確認であり、実便の計算成功ではない。配置記録は `output/cluster-deployment/onboard-20260923/runtime-install-report.json` と `stage-four-evidence/report.json` にある。

`tools/cluster/serve_controller.py` は `settings.scenarios` に既存の `C:/master-course/output/scenarios` を指定できる。計算出力は隔離した `settings.outputs` に置いたまま、React画面の既存 `/desktop/scenarios` と `/scenarios/{id}/simulation/prepare`・`/cluster/jobs` 経路をそのまま用いる。既存シナリオを単に一覧表示したことと、全シナリオが正式実行の入力契約を通ることは別である。

`tools/cluster/real_shibu24_batch.py` は原本SHA、6パターン・582便、事業者IDと正の距離根拠、実便224件、親シナリオ前後ハッシュ、正式Prepare、車両・充電器の存在を検査し、16台へ1件ずつ固定割当するbatchを作る。`tools/cluster/batch.py` が冪等な投入、完了待ち、ZIPハッシュ照合を行う。16/16件の完了と独立物理・費用・入出力原本の照合は、実行後に別々に判定する。

正式研究採用には、正式fleet契約、全便画面照合、実道路距離・実受電設備値、年度整合、連続期間のBESS、目的関数に対応する最適性の範囲など、未解決のゲートが残る。診断の `COMPLETED` をそれらの代替にしない。
