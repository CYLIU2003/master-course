### メモリ停止の特定根拠と今回の変更

native logではbarrierが36反復で目的値4,000,000へ収束し、
362.63秒時点でbarrier内部の最適状態になった。その後391秒付近の基底生成中に
`Crossover changed status from Optimal to Memory Limit` となった。
barrierそのものの未収束とは区別できる。観測最大メモリがsoft18GB未満でも、
終了statusはmemory_limitなので「メモリ問題なし」とはしない。

MIPのcrossoverを無効化するにはrootとnodeの両方をbarrierにする必要がある。
今回はこの条件を満たす専用profileを追加した。整数変数や物理制約を連続緩和して採用する変更ではない。
crossoverなしでは数値精度や反復数が変わり得るので、既存の物理許容差を維持して再検査する。
[Gurobi公式Crossover仕様](https://docs.gurobi.com/projects/optimizer/en/current/reference/parameters.html#crossover)。

到達経路は、BFF `RunOptimizationBody` → `OptimizationConfig` → Phase3
`_configured_stage1_gurobi_search_controls` → native Stage1 → canonical metadata → 診断summary。
defaultや既存profileは保持し、成功・Stage1失敗・Stage2失敗のmetadataに実効Crossover値を残す。
診断コードは総費用を充電目的値から作らず、canonicalのcost_breakdownを併記する。
数式・料金・BESS領域・後続網・時刻表・operator・車両集合は変更しない。

設計: [barrier_no_crossover設定](../../config/shibu21_23_barrier_no_crossover_diagnosis_20260921.json)。
1回の新規Prepare/5月前日計画に限定し、4threads・soft18GB・600/120秒・wall1200秒・1%・seed42を維持する。
通常処理はローカルscript、終了時に既存タスクへ1回だけ通知。メール・全12週・自動再試行はこの診断に含めない。

## 4. 「最適」と言える範囲

最小化問題について、実行可能解の目的値Uと証明された下界Lがあるとき、
この診断ではgap=(U−L)/|U|を用いる。今回のStage1では
(4,157,098.222019−4,000,000)/4,157,098.222019=3.779036%。
これはStage1の目的関数に対する証明の幅であり、実績総費用が3.78%高いという意味ではない。

Stage1は充電を緩和した配車、Stage2はその配車を固定した充電の問題である。
それぞれの1%目標を達成しても、配車と充電を同時に決める統合問題の1%以内とは証明していない。
さらに、予測入力による最適計画と実PVでの実行費用は別の評価である。

最適性の主張には、対象の目的関数、制約、入力、gap、終了理由をセットで示す。
「GurobiがOPTIMALだから研究モデル全体で最適」「Stage2が0円だから運行費0円」は使用しない。

## 5. 先生からの質問への説明案

**太陽光が多いのに高額だったのはなぜか。**
旧68f2f4e5の1月と5月の差223.49万円の95.48%は、設定した受電超過費の差だった。
計画の将来区間ではBESSを使えるのに、その時刻の実行規則では初期残量を守るという不整合も確認した。
それに対処しているが、修正の実績削減額はまだ測定していない。
月ごとに配車・予測・日付も異なるため、太陽光が増えたこと自体の因果効果にはできない。
[旧結果の費用分解と原本](MONTHLY_RESERVE_COST_DIAGNOSIS_20260921.md)。

**公平な比較になっているか。**
各月内に完全に収まり、祝日を含まない最初の月曜～日曜を、PVと費用を見る前に選んだ。
平日5日・土曜1日・日曜/休日1日、同じ設備・料金・解法条件という比較範囲では揃えている。
ただし各月1週なので月平均・季節平均・年平均は推定できない。
月別の違いは「選択週の差」と表現する。PV単独の効果には同じ日付・時刻表・車両・初期状態の対比較が別途必要。

**実際の営業所を再現しているのか。**
2026年の時刻表テンプレートを2025年の評価日に適用したモデルで、2025年の実運行そのものではない。
営業便距離は停留所座標由来の地理的代理値であり実道路距離ではない。
予測は2024年だけから作った季節標準カーブで、Solcastの予報精度を評価したものではない。
200kW基準・500円/kWhの超過ペナルティはモデル仮定で、実電力契約として確認済みではない。
正式fleet contract等の研究承認条件も残る。
[元の入力条件・制約](SHIBU21_23_MONTHLY_RESERVE_RESULTS_20260920.md)。

**今回、何が進歩したのか。**
旧denseと等価な端点表現で係数を67.6%、最大nativeメモリを22.3%削減した既往診断がある。
日別路線検査の誤判定も修正し、物理的に成立する候補を正しく評価できるようになった。
最新では計算停止をcrossoverに絞り込めた。一方、これらを費用削減や統合最適性の達成とは呼ばない。
[表現比較](STAGE1_CHARGE_WINDOW_SUPPORT_20260921.md)・[検査修正](ROUTE_BAND_SERVICE_DAY_FIX_20260921.md)。
