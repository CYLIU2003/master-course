# 月別計算: 1月127時間目の数値的不成立への対応

## 確認した失敗

固定 `c022ece753fad8121a54dc54c2b3a4de8b96b3df` は1月・4月の前日計画検査を通過したが、月別計算の1月 `2025-01-06`、hour126（127時間目）のStage2で停止した。126時間を受理、完了週は0/12。`commands.log` は週間監査に到達していないため未生成。旧failure、native log、queue記録は保持し、完了メールは送っていない。

旧制御先: `output/monthly_auxiliary_timeline_20260922/`。失敗summary SHA256は `5f41c8bacf953afaad1597806d8283d9d282495ef098e4e3fae0921275eaae8c`。

## 再現と原因の根拠

保存された配車・hour126開始状態・同じ入力から全充電モデルを再構成した。native fingerprintは旧ログと同じ `0xf590abea`（APIの符号付き整数表現は -175068182）。初回の比較スクリプトは符号変換を欠いて停止したが、モデル差ではなかった。その診断失敗記録も残す。

全モデルMPS SHA256: `71370a0ff4ffc80d1b8de80f16e16d1c8b7b77bf0c04dfaee6112b8aa85a05fc`。80,826行・79,012変数、同じモデルを各15秒で比較した。

|---|---|---:|---:|---:|
| 旧設定のまま | INFEASIBLE / 解0 | 4.004 | 未定義 | 未定義 |
| NumericFocus=3のみ | OPTIMAL / 解1 | 3.157 | 0% | 7.894e-11 |
| Cuts=0のみ | OPTIMAL / 解4 | 8.986 | 0.0000155% | 6.702e-11 |
| Method=1のみ | INFEASIBLE / 解0 | 3.972 | 未定義 | 未定義 |

根拠: `hour126_model_diagnosis/profiles/summary.json` と各native log。保存IISを単独で読み直すと可行となり、終端上限との差も診断上1.76e-11 kWhだった。単独IISの挙動だけで判断せず、全モデルで旧失敗と新設定の可行解を確認した。数値計算による不成立判定と判断するが、特定のcut実装の欠陥とまでは断定しない。

[Gurobi公式の数値問題ガイド](https://docs.gurobi.com/projects/optimizer/en/current/concepts/numericguide/numeric_parameters.html)のNumericFocusは数値計算の慎重さを上げる設定であり、性能への影響があり得る。

## 変更と不変条件

`OptimizationConfig.stage2_gurobi_numeric_focus` を追加し、既定値は0のまま。新しい月別設定だけ、前日0・毎時3を実行前に宣言する。入口の設定生成→rolling設定→実ソルバー→成功/失敗metadata→169原本の独立監査まで接続した。欠落、型違い、宣言違いを監査で拒否する。失敗した時間だけの再試行はない。

SOC上下限・初期状態・終端条件・物理許容差・BEV運行・完全後続網・時刻表・BESS方針・目的関数を変更しない。BESSは20～80%、PVバス優先、余剰蓄電、追加予備と終端復元なし。前日Presolve2/Method1、毎時Presolve0/Method0、MIPFocus1、4threads、1800/120/15秒、目標1%は維持する。数式の可行領域は不変だが、有限時間の探索結果は変わり得るため、旧成功週を新条件の結果へ流用しない。

## 検証と次の実行

局所診断でhour126/127は、実際の残量・燃料・位置・充電セッションを引き継いで通過し、gap0%。それ以降は未検証。二時間診断は回帰試験後にclean固定版から連続検証するため制御停止し、記録を保存した。

回帰試験は保存した全モデルを圧縮fixture化し、数値対策で可行解を得る一方、初期SOCを1 kWh増やして本当に終端上限を超えるモデルは拒否することを検証する。過去の4月境界・3月SOC引継ぎも新設定で確認する。回帰試験通過は全12週の成立証明ではない。

新制御先は `output/monthly_auxiliary_numeric_20260922/`。一度きりのスクリプトが以下を逐次実行する。

1. 固定版・helper hash・入力hashを照合し、保存hour126開始状態から残り42時間を別出力で連続検証する。
2. 各時間の成立・Stage2 gap・数値品質・BESS収支・状態引継ぎを確認し、過去126時間を文脈として全週の独立物理検証を行う。この結合は診断専用で、今回の月別結果や費用として採用しない。
3. 通過した場合だけ新規Prepareから全12週を開始する。全月計算でも時間ごとの状態、独立物理、確定会計、元metadataを監査する。
4. 失敗時は停止し、既存タスクへ1回だけ通知。全12週監査・最終図表の確認前に完了メールは送らない。通常処理はAIを呼ばない。

新しい設定で全月が通過する保証はない。研究採用はBLOCKED、DIAGNOSTIC / NOT USED FOR RESEARCH CONCLUSIONSを維持する。Stage1目標gap未達、二段階の統合総費用最適性、入力由来の既存制約は別の未解決事項。自己レビューと独立レビューを区別し、独立研究承認は未取得。
