# 計画・実行条件の統一と「最適」の判定

2026-09-21。対象は渋21–23のPhase 3配車・固定配車充電・毎時rolling。
前版 `68f2f4e5` の全12週・送信済みメールは保全する。新しい結果へ流用しない。

## 最適とは

同一の入力・制約を満たす実行可能な計画集合を F、明示した費用を C とすると、
最適値は `min { C(x) : x ∈ F }`。実行可能な計画が見つかっただけでは最適とは言えない。
最小化では得られた計画の費用 U が上界、正しく証明された下界 L が下界で、
正の費用なら gap = `(U-L)/|U|`。100万円の計画と98万円の下界ならgapは2%。
1%を目標にした場合は未達である。ゼロ目的値は別扱いとし、欠けた下界を0に置換しない。

今回のPhase 3は、配車の連続充電緩和と、その配車を固定した充電を別々に解く。
両段階で1%を満たしても、配車と充電を統合した大域的最適解の証明にはならない。
予測に対する目的値と、実際のPVを再生した確定費用も別である。
実費の比較は全168時間の物理検証・終端在庫復元・確定会計通過後に行う。

## 修正

新ポリシー `evaluation_target_every_prefix` を追加。旧ポリシーの意味は保持する。
保護残量 E* は評価開始時のBESS終端目標から固定し、観測後の残量から再定義しない。
各発行ブロック b の全区間 t に、次の制約を適用する。

`E_start(b) + η_charge × Σ(grid_to_BESS) − Σ(BESS_to_bus)/η_discharge ≥ E*`

和はそのブロック開始からtまで。ブロック内の未観測PVは含めない。
未来ブロックの開始残量はモデルのSOC変数なので、以前のブロックで蓄えた予測PVは使える。
全週のPVをゼロと仮定する方式ではない。全ブロックに同じ制御則を適用することで、
「今の指令では使えない保護残量を将来だけ借りる」見込みをなくす。
日次計画、Stage 1連続充電緩和、毎時の将来予測区間に共通の関数を使う。
実行する先頭区間の従来の安全制約も保持する。
発行間隔はdesignの60分をDAにも明示して、既定15分との不一致を防ぐ。

物理20–80%、PVのみのBESS充電、週末復元、途中のBEV目標、料金、500円/kWhの超過費、
車両・時刻表・operator・距離・完全な後続ネットワークは変更しない。
保護残量3000 kWhという運用制約自体は残るため、その保守性の最適性は証明していない。

配車には各出発日で同時に走る便の最大数を下界として追加した。
同時に走る2便を同じ車両に割り当てられないので、日ごとの下界の和は車両日数の有効な下界になる。
全週の車両数の下界を単に7倍する計算はしない。到着と出発が同時なら重複扱いしない。
深夜をまたぐ便も、費用計上と同じ出発日へ分類する。制約を緩めず、探索の下界を強くする修正である。

探索設定 `bounded_presolve` はPresolve=1、PrePasses=3、MIPFocus=1、Heuristics=0.2。
前処理が制限時間を占有した既存ログへの対処候補であり、性能改善は計測して判定する。
[Gurobi公式のパラメータ指針](https://docs.gurobi.com/projects/optimizer/en/current/concepts/parameters/guidelines.html)でも、前処理時間を減らす手段として少数のPrePassesが示されている。
APIと月別スクリプトから同じ設定を選べ、nativeメタデータへ保存する。

## 検証と診断の範囲

- 3時間の再現例（初期50 kWh、PV 10/0/10 kWh、中央の需要10 kWh）で、旧方式は最初のPVを捨てて後で100円を買電。新方式は先に10 kWh蓄え、費用0.1円。0.1円はこの人工例の微小な充電費。実際の月別削減率へ外挿しない。
- 同一需要・初期状態・料金の人工例で、早い時間のPVを増やしても費用が増えないことを確認。
- 48時間のnative rollingで、予測が明るく実際は暗い場合と途中から暗くなる場合に、安全残量・収支・最後の初期残量への復元を確認。

- 保存フローの独立監査を拡張し、DAとrollingの未来ブロックも再計算。未来の保護違反を入れたデータを拒否する。
