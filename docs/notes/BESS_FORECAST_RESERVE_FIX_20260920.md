# 予測誤差後のBESS週末復元を守る修正

2026-09-20の「問題がなくなるように完全に直す」という指示を受け、PVのみのBESS充電と週末の初期残量復元を維持して修正した。旧4月の不足54.411 kWhは、失敗後の補給やSOC書換えで埋めない。新しい条件を全12週に共通適用し、すべて新規Prepareから実行する。

## 数式と変更範囲

評価開始時のBESS残量を `E*` とする。現在観測した残量 `E_h` と、次の1時間に出す指令から、PVがゼロの場合の残量を各15分slotで計算する。

`L_t = E_h + η_charge Σ g_to_bess − Σ b_to_bus / η_discharge >= E*`

今回のBESSはPV専用なので `g_to_bess = 0`。未来のPV充電をこの不等式の財源として数えない。実際に蓄えた `E*` 超過分は放電できる。ハードウェアの20–80%範囲は保持し、このキャンペーンの `E*=3,000 kWh`（容量の50%）を別の運用上の予備残量として課す。

各rolling窓のBESS終端も `E*` の等式にする。旧条件のday-ahead BESS予測境界への等式は、新しい予備残量と両立しない場合があるため使わない。BEVの中間SOC目標は従来の固定day-ahead境界を維持し、評価週末はBEV・BESSとも元の初期残量へ戻す。BESSの日次の中立性を追加するものではなく、現在から最大24時間先のrolling窓末を固定する。

新しい宣言は `bess_forecast_reserve_policy=evaluation_target_zero_pv`。未指定の既存設計は `physical_floor_only` とし、過去の設計を暗黙に変更しない。設定・date-series契約・canonical metadataの不一致、終端を消すminimum-onlyとの併用、未凍結の目標、非対応の供給源・日次収支・ハード受電上限を拒否する。

## なぜ今回の停止を防ぐのか

実行器はBESSへのPV充電を指令量以下に制限し、実績が不足した分だけ減らす。したがって、指令区間の実残量はゼロPV下界以上・予測軌道以下に収まる。毎時 `E*` を確保することで、旧4月のように週末用残量を将来のPVに依存して借りる状態へ入らない。

残量が予測より低くなっても `E*` 以上なら、前の計画の残り区間のBESS放電をその差だけ減らし、バスへの系統供給へ置き換える実行可能な継続を構成できる。BESSを `E*` へ戻す計画では、その差以上の累積放電が残るためである。窓を延ばす部分は、BEV境界から固定day-ahead車両計画を継続し、BESSを `E*` に保って系統でバスを供給できる。これは実行可能性の説明であって、実装が求解後に計画を補修する処理ではない。実装は追加制約を入れたnativeモデルを毎回求解する。

この説明の範囲は、現在の実行器、非負の実績PV、PV専用BESS、BESS出力・SOC制約、確定した車両充電指令、およびバス供給の有料受電超過を認める現在のシナリオである。需要予測誤差・故障・ハード受電上限・求解時間内の探索成功・全ネットワークの統合最適性の保証へ拡張しない。

## 到達経路と監査

`configure_doc` → 日付別Prepared → `ProblemBuilder` → `RollingReoptimizer`による初期目標の凍結 → `pv_execution_reserve`のnative制約 → `execute_pv_prefix` → 次の実状態、という既存経路で処理する。

週間監査は `scripts/benchmarks/audit_bess_forecast_reserve.py` を追加し、168回すべての指令と実績再生の原本から、ゼロPV下界、SOC保存式、時刻間の引継ぎ、系統からBESSへ供給していないこと、各窓末・週末の目標を独立検算する。solverの保護フラグだけで合格にしない。native/実績再生336ファイルのSHAを残し、報告生成でも照合する。

完了図の保存先が旧版と衝突する不具合も修正した。新条件は専用の結果・図・監視・通知記録へ出し、停止が発生した場合は失敗を成功数へ数えず、途中報告を停止状態へ更新してから一度だけ通知する。未完了のメールは送らない。

## 検証と解釈

48時間ずっと実績PVゼロ、および途中からゼロとなるnative rolling連鎖を検証した。元の初期残量の凍結、旧day-ahead BESS境界の不使用、BEV境界の保持、実績余剰の放電、設定競合の拒否、物理下限だけの旧設計との互換性を回帰で確認した。追加の検証件数・新実行の固定SHAは [実行記録](MONTHLY_RESERVE_EXECUTION_20260920.md) に記す。

初期在庫を守る分だけ利用可能なBESS容量は減るため、購入電力・ピーク・費用が改善するとは事前に主張しない。数式変更前の成功3週を新条件へ混ぜない。修正のローカル検証と全12週の完了、独立した研究承認は別の判定とし、**DIAGNOSTIC / NOT USED FOR RESEARCH CONCLUSIONS、研究採用BLOCKED**を維持する。
