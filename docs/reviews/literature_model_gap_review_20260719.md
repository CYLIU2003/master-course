## 1. 結論

現在の研究モデルは、失敗作ではない。264便を15分刻み、候補接続の削減なしで担当し、運行・SOC・充電器・受電上限の違反がない計画を得るところまでは到達している。これは研究の土台として十分に価値がある。

一方で、現状の正式結果から言えるのは、**「全便を担当できる二段階の計画を作れた」**までである。研究目的に記載している、**「車両割当、充電、PV、BESSを一体で最適化し、費用とCO2を改善した」**という主張は、まだ実行結果によって証明されていない。

モデルがいつまでも良くならないように見える最大の理由は、モデルの部品不足よりも、次の四つが同時に起きているためである。

1. 研究で証明したいことが、統合最適化、二段階計画、ALNS、晴雨比較、毎時見直しへ広がっている。
2. 現在の実行経路は二段階なのに、研究説明には「一体で最適化」と書かれている。
3. 正式15分結果では、PVとBESSを使っておらず、電池を一日で大きく使い切れる設定になっている。
4. 「実際に買った電気の費用」と「走行量から仮に見積もった費用」が混在している。

したがって、新しい機能を増やす前に、**研究の主張、日をまたぐ電池条件、費用の定義、比較実験の条件**を固定する必要がある。

## 3. 最も重大な問題

### P0-1. 研究上の説明と、実際に解いている問題が一致していない

研究概要では、車両割当、充電、PV、系統電力を「一体で最適化」するとしている。しかし、現在の正式な Phase 3 は次の順番で処理する。

1. Stage 1で一日の車両割当を決める。
2. 車両割当を固定する。
3. Stage 2で充電、PV、BESS、系統電力の使い方を決める。

Stage 2で充電費が高い、または設備上使いにくいと分かっても、その情報を使ってStage 1の車両割当を選び直す仕組みはない。このため、現在の方法は**二階層の逐次計画**であり、全要素を同時に比べる統合最適化ではない。

この構成自体が悪いわけではない。[Hu et al. (2025), No63](../../先行文献/No63.pdf)も、大きな問題を分けて解く方法を採用している。ただし同論文では、分けた問題の間で情報を返し、全体として良い解に近づける仕組みを持つ。現在のモデルにはその往復がない。

**必要な対応:**

- 修士論文の主張を「二階層計画」に変更する。
- または、Stage 2の結果をStage 1へ返して割当を見直す処理を追加する。
- 統合最適化を主張したい場合は、小規模ケースで同時最適化した結果と比べ、二段階化による費用差を示す。

### P0-2. 正式baselineが、一日の初めの電池を使い切ることで成立している

正式15分baselineでは、32台すべてがBEVとして使われている。各車両は314 kWhの電池を80%から開始するため、全車合計の初期残量は8,038.4 kWhである。一日の終了時は4,369.8 kWhまで低下し、**初期の電気を約3,668.6 kWh消費**している。一方、当日の充電は約32.3 kWh、充電した車両は3台だけである。

| 指標 | 正式15分baseline |
|---|---:|
| 使用BEV | 32台 |
| 初期の車両電池残量合計 | 8,038.4 kWh |
| 終了時の車両電池残量合計 | 4,369.8 kWh |
| 一日で減った電池残量 | 3,668.6 kWh |
| 当日の充電量 | 32.3 kWh |
| 充電した車両 | 3台 |
| 最も低い終了SOC | 10% |

この結果は「その日だけなら走れる」ことを示す。ただし、翌日も同じ運行を続けられることや、その日の運行に必要な充電費を示していない。PVの有無やBEV・ICEの費用を公平に比べる場合、初日の無料の電池残量を片方だけに使わせてはいけない。

[中野ほかのモデル予測型逐次充電計画](../../先行文献/電気バスの低炭素運用に向けたモデル予測型逐次充電計画の導入評価.pdf)は、二日分を計画し、一日実行後のSOCを次の計画へ引き継ぐ。[Xiao et al. (2026), No61](../../先行文献/No61.pdf)も、車両電池と定置型蓄電池の残量を時系列で示している。

**必要な対応:**

- 代表日比較では、全BEVの終了SOCを開始SOCへ戻す。
- または、二日以上を連続して計算し、前日の終了SOCを翌日に引き継ぐ。
- 終了SOCを低くしてよい場合は、翌日に残す電気の価値を費用へ加える。
- 晴天、雨天、grid-onlyの全ケースで同じ境界条件を使う。

### P0-3. 報告される電気代が、実際の買電額だけではない

正式baselineの会計総額は707,747.0円で、内部の費用項目同士は一致している。しかし、電気関係の66,438.1円のうち、実際の系統購入32.3 kWhに対応する額は581.7円で、65,856.4円は走行量から先に見積もった暫定費用として残っている。出力自身も`objective_is_actual_cost=false`、`research_cost_kpi_eligible=false`としている。

したがって、現在の707,747円を「一日の実際の運行費」や「最適化後の電気代」として発表してはいけない。会計式が一致することと、研究で意味のある費用になっていることは別である。

**必要な対応:**

- 研究用費用は、充電、給油、車両使用、需要料金など、実際に発生した流れから再計算する。
- 初期の電池残量を消費した分は、終了SOCを戻すか、消費した電気の補充費用を加える。
- 暫定費用はStage 1の探索用に限定し、最終KPIへ混ぜない。
- ICEについても、距離からの燃料見積りなのか、給油計画なのかを明記する。

## 5. 研究として不足している証拠

### 5.1 正式なPV・BESS結果

正式15分baselineはgrid-onlyであり、PV、BESS、天候差を評価していない。晴天・雨天の既存結果は、60分刻み、候補接続上限8、Stage 1 gap約13%またはそれ以上、実行条件によってdirty worktreeを含む。したがって、現時点ではPVやBESSの効果を修論の主結果として確定できない。

必要なのは、同じcommit、同じ便、同じ車両、同じ初期・終了SOC、同じ設備、同じseedで、PV時系列だけを変えた15分結果である。

### 5.2 24時間の毎時見直し

現在確認済みなのは05:00の計画から06:00へ状態を渡す1回だけである。「毎時見直しを完成した」と言うには、少なくとも次が必要である。

- 一日を通した24回の状態引継ぎ
- EV SOC、BESS SOC、その時点までの最大受電の引継ぎ
- 実行済み時間帯の費用・電力を二重に数えない集計
- 途中のどの時刻でも不可行にならないこと
- 一日固定計画、毎時見直し、完全予測の三つの比較

### 5.3 予測誤差と走行電力誤差

PV予測を差し替える機能は実装されているが、結果がない。さらに、先行文献ではPVだけでなく走行に必要な電気の誤差も重要とされている。

最小限の実験は次でよい。

- PV: 誤差なし、少なめ10%、多め10%、時間ずれ
- 走行電力: 基準、+10%、-10%
- 評価: 未担当便、SOC違反、費用、CO2、最大受電、PV利用率

確率分布や高度な頑健最適化を直ちに実装する必要はない。まず、同じモデルへ入力誤差を与えたときに、毎時見直しが何を改善するかを示す。

### 5.4 比較対象

提案法だけを示しても、改善量は分からない。最低限、次の比較が必要である。

| ケース | 役割 |
|---|---|
| ICEのみ、または現行運用に近い計画 | 導入前の基準 |
| grid-onlyの一日固定計画 | PV・BESSなしの基準 |
| PV・BESSありの一日固定計画 | 日次最適化の効果 |
| PV・BESSあり、予測誤差を受ける固定計画 | 見直しなしの弱点 |
| PV・BESSあり、毎時見直し | 提案法 |
| 完全な予測を与えた計画 | 到達可能な参考値 |

## 6. 今は追加しなくてよいもの

文献フォルダには、V2G、電力系統の電圧、周波数調整、急速な走行中充電、強化学習、複数営業所などを扱う研究も含まれる。しかし、これらは現在の修士論文を成立させるための必須要素ではない。

次は、現在の核心が固まるまで追加しない。

- V2Gや電力市場取引
- 配電線の電圧・潮流計算
- GA、ABC、ALNSの比較拡大
- 車載電池劣化費。実測値や根拠ある係数を用意できない場合
- 複数営業所、複数日、運転士勤務の同時拡張
- 5分刻みでの全264便本計算

機能を増やすほど研究が強くなるわけではない。今は、現在の二階層計画を公平な条件で最後まで実行し、比較可能な結果を作る方が重要である。

## 7. 推奨する研究の立て直し方

### 7.1 推奨する研究題目

> 太陽光発電を有する営業所におけるBEV・ICE混在バスの二階層運行・充電計画と毎時見直しの評価

「統合最適化」や「大域最適解」は、現在のPhase 3には使わない。「二階層計画」「制限時間内に得た可行解」「毎時の充電計画見直し」と表現する。

### 7.2 研究で答える三つの質問

1. 固定した便と車両に対して、全264便を違反なく担当できるか。
2. 公平な開始・終了SOC条件の下で、PVとBESSが費用、CO2、最大受電をどれだけ変えるか。
3. PV予測が外れたとき、毎時の見直しが固定した一日計画よりも違反や追加費用を減らせるか。

この三問に答えられれば、修士論文として十分に筋が通る。ALNSや高度な頑健最適化は、時間が残った場合の追加検討に回せる。

## 8. 修正の優先順位

### 最優先: 比較の土台を直す

1. BEVの終了SOCを開始SOCへ戻す正式比較条件を追加する。
2. 最終KPIから暫定走行費を除き、実際の電力・燃料の流れから費用を再計算する。
3. 研究説明を「統合最適化」から「二階層計画」へ統一する。
4. PV・BESSありの15分固定入力を作る。

### 次: 提案法を最後まで動かす

1. 一日計画を一度作る。
2. 車両割当を固定したまま、充電計画を毎時更新する。
3. 24回の状態引継ぎを完走する。
4. 実行した1時間分だけを積み上げて、一日のKPIを再集計する。

### その次: 比較実験を揃える

1. 晴天・雨天または高PV・低PV
2. PV予測誤差
3. 走行電力±10%
4. seed 42、43、44
5. 候補接続上限8、16、32、削減なし
6. 60分、30分、15分の時間刻み

## 9. 次の正式結果の受理条件

次の条件をすべて満たした結果だけを、PV・BESS・費用比較の主結果として使う。

- clean commitと固定入力hashが記録されている。
- 15分刻みである。
- 264便担当、未担当0、重複0である。
- 接続、SOC、充電器、受電、電力収支の違反が0である。
- fallback、事後修復がない。
- 開始SOCと終了SOCの公平性が説明できる。
- PV、BESS、天候の入力が実際に適用されている。
- 費用は実現した電力・燃料の流れから計算されている。
- `research_cost_kpi_eligible=true`になる。
- Stage 1が時間切れなら、gapと「最適性未保証」を併記する。
- 一日固定計画と毎時見直しを同じ入力で比較する。

## 10. 総評

厳しく言えば、現在は**可行性の実装は進んだが、研究上の比較設計が追いついていない**。モデルの制約をさらに増やすことより、次の三点を直す方がはるかに重要である。

1. 一日の初めと終わりの電池条件を公平にする。
2. 実際の充電・給油に基づく費用へ統一する。
3. 二階層計画と毎時見直しを、24時間・予測誤差ありで比較する。

この三点を完了すれば、現在のコード資産を捨てずに、研究の主張と実行結果を一致させられる。現段階で必要なのは新しい大規模モデルではなく、**今あるモデルを研究として成立する条件で閉じること**である。
