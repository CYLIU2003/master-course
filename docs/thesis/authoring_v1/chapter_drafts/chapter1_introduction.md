# 第1章 序論

## 1.1 背景

路線バスの脱炭素化では、ディーゼル系車両を電気バスへ置換するだけでなく、限られた車両・充電器・電力設備の下で全便を成立させる運用設計が必要である。電気バスは走行時排出を低減できる一方、充電可能時間、SOC、受電電力、太陽光発電（PV）、蓄電池（BESS）の状態が時刻を介して結合する。既存ICE車両を含む移行期には、どの便をBEVまたはICEへ割り当てるかも同時に重要となる。

この問題では、solverが解を返したことと、その解が現実の時刻・エネルギー・会計契約を満たすことは同義ではない。便間の折返し、回送、運転者、距離、SOC、充電器競合、日末状態を独立に確認しなければならない。また、大規模MILPのtime-limit incumbentを、証明済みの大域最適解と誤認してはならない。

## 1.2 研究目的

本研究は、混合BEV/ICEの便割当候補と、PV・BESSを含む営業所エネルギー運用を二段階で接続し、物理検算、24時間Rolling、会計照合までを再現可能な証拠鎖として構築することを目的とする。対象は弦巻営業所の264便であり、同一WEEKDAY時刻表に対してSUNNYとRAINの2つの固定PV条件を比較する。

## 1.3 研究課題

RQ1は、二段階Phase 3が264便を欠落なく割り当て、独立物理検算と24/24 Rollingを通過する解を生成できるかである。RQ2は、固定PV条件差により、有限候補内で選ばれるBEV/ICE配車、PV・BESS・系統・燃料フロー、モデル内評価額がどう異なるかである。RQ3は、その結果をSHA、prepared input、artifact、式–実装対応とともに再検証可能にできるかである。

## 1.4 貢献

本研究の貢献は三点である。第一に、Stage 1候補生成とStage 2エネルギー運用を明示的に分離し、有限候補内の選択であることを隠さない。第二に、日初計画、24回のRolling、独立物理検算、canonical実行日会計を別ゲートとして監査する。第三に、2ケースの96スロット系列、費用分解、候補順位、主張–証拠対応を再生成可能な派生成果物として固定する。

## 1.5 主張範囲

本稿は統合MILPの大域最適性、一般的な雨天効果、実支出、LCC、導入採算または実運用可能性を証明しない。中心主張は「固定2ケースにおいて、評価した有限候補集合から選択されたPhase 3二段階解が、物理・Rolling・会計ゲートを通過した」である。

## 1.6 本稿の構成

第2章でシステムと既往研究、第3章で数理モデル、第4章で実験設計、第5章で結果、第6章で考察、第7章で再現性と妥当性、第8章で結論を示す。

## 1.7 社会背景と運用上の論点

交通分野の電動化は、車両単体の動力源転換だけでは完結しない。路線バスは、定められた時刻に出発し、前便の遅れや回送時間を吸収しながら次便へ接続する公共サービスである。BEVを導入しても、充電のために欠便が生じるなら運用案として成立しない。また、営業所に多数の充電器や大容量BESSを置けば技術的余裕は増えるが、設備容量を無制限に仮定すれば現実の受電・空間・費用制約から離れる。このため、車両、時刻、エネルギー、設備を同じ時間軸上で扱う必要がある。

PVの導入にも時間的不一致がある。日中のPV発電が多くても、バスが路線上にあれば直接充電できない。BESSはこの不一致を緩和するが、充放電電力、容量、効率、終端SOCに制約される。PV抑制が生じた場合、それはPV設備の無効性だけでなく、需要時刻と設備の組合せを示す。一方、低PV時に系統電力を購入できても、料金と車両日費用の組合せによってはICE担当の多い配車が有限候補内で選ばれる。本研究は、このような相互作用を便単位と15分単位の双方で追跡する。

## 1.8 研究ギャップ

先行研究には、電気バスの車両スケジューリング、充電計画、PV・BESS運用、頑健最適化が存在する。しかし、研究用solverの出力から、どの入力で、どの便を、どの車両が担当し、Rollingで何が実行され、最終費用がどのledgerに基づくかを一貫して追跡できなければ、結果の再検証は難しい。とくに、大規模計算ではtime limit、近似目的、候補絞込みが入り、`OPTIMAL`やgapの対象を取り違えやすい。

本研究が埋めるのは、既往の全ての数理機能ではなく、対象システムにおける「解の成立範囲を証拠とともに説明する」ギャップである。Stage 1の探索品質が不十分でも、Stage 2で実行可能な候補が得られ、物理・Rolling・会計を通過した事実には意味がある。同時に、それを大域最適解と呼ばない境界も研究結果の一部である。

## 1.9 用語の定義

本稿で「SUNNY」は2025-08-05由来の高PV条件、「RAIN」は2025-08-10由来の低PV条件を表すcode nameである。RAINは日曜運行を意味しない。「実行可能解」は実装済みの便・時刻・SOC・設備制約と独立検算を通過した解である。「評価額」は本モデルが有効化した24時間費用成分の合計であり、実支出ではない。「正本」はGit SHA、scenario、Prepared input、artifact hashで特定された変更不能な証拠を指す。

## 1.10 研究成果の判定方法

RQ1は、欠便、物理違反、Rolling未完了、会計不一致のいずれかがあれば支持されない。RQ2は、非PV入力が一致しないか、PV曲線差または配車差をhashで追跡できなければ比較不能である。RQ3は、gapの対象、有限候補、費用源、未実装費用を明示できることを要求する。この反証条件を先に定めることで、結果に応じて受理基準を変更することを防ぐ。

## 1.11 修論としての到達範囲

本稿は、研究システムの全機能を完成させることではなく、凍結済み結果を研究課題、数式、実装、入力、結果、主張へ一対一で対応させることを到達点とする。追加機能や長時間計算で見栄えのよい値を探すのではなく、現時点で支持される事項と不足証拠を分離する。

題目候補は「BEV/ICE混成バス営業所における二段階配車・充電計画とPV条件差の監査可能な評価」である `[指導教員判断]`。題目に「最適化」を含める場合も、本文では統合大域最適性がないことを明記する。成果は実行可能解、固定反実仮想、再現可能な証拠体系の三点に限定して評価する。

本研究の読者は、最適化研究者だけでなく、交通運用またはエネルギー運用を専門とする者を想定する。このため内部class名だけで説明せず、入力、意思決定、制約、実行、検算を日本語で示す。一方、再検証に必要な実装名、JSON field、hashは付表に残し、説明の平易さと技術的追跡性を両立する。

この方針により、本文は研究上の問いと答えを中心に置き、詳細な監査情報は付表から辿れる構成とする。
数値の由来と解釈の境界を同時に読めることを重視する。
