# 5. 結果を失わずに障害を切り分ける

最初に[実行手順](03_RUNBOOK.md)で操作対象を確認する。原因を確かめる前に全PCを再起動したり、旧出力を消したり、同じ週を別PCへ再投入したりしない。まず確定済み結果を保持し、障害の範囲を限定する。

## 最初の確認表

次を作業記録へ残す。資格情報やprivate worker台帳の全内容は貼り付けない。

| 項目 | 確認内容 |
|---|---|
| 対象 | 親scenario、週開始日、operation、controller URL、queue |
| 版 | 開発HEAD/dirty、計算固定SHA、Prepared ID/hash、親hash |
| 試行 | job ID、attempt ID、worker ID、受理済みか、最後の観測時刻 |
| 工程 | 入力準備／待機／前日計画／毎時Rolling／回収／検算／図表 |
| 状態 | 原state、現在のworker応答、報告revisionの判定を別々に記録 |
| 原本 | state、元ログ末尾、失敗記録、設定、計画・会計・検証、ZIP hash |
| 資源 | 総RAM・空きRAM・実メモリ・設定上限・license予約と待機理由 |

ログの一行やUIの赤色だけで原因を決めない。計算、通信、回収、検算、描画は別工程である。

## 症状から確認先を選ぶ

| 症状 | 確認と対処 | 避けること |
|---|---|---|
| 画面/APIが開けない | operationのsettings、port、管理サーバーの記録を確認。保存済み結果は直接読める | API停止を遠隔求解の終了とみなす |
| SSH timeout・受理応答消失 | 同じattemptをworkerへ照会する。照合できるまでPC枠・license予約を保持 | 新しいattemptを別PCへ自動投入する |
| 認証拒否・host key不一致 | 接続設定と登録対象を確認。必要な人間の対応を具体的に報告 | host key検査を無効化する、資格情報をログへ出す |
| 親stateはRUNNING、報告は12/12 | 観測日時、元job、原ZIP、復旧receipt、latest revisionを照合する | 親stateだけを根拠に未完了週を再計算する |
| source.sqlite3がない | 実行rootと配置releaseを確認。正しい既存snapshotの配置とhashを照合する | PrepareからODPT取得・DB再生成を行う |
| 親とPreparedが不一致 | 変更箇所を特定し、新実験版で必要な比較入力をPrepareし直す | hashを手で書き換える、旧入力を現行版と呼ぶ |
| QUEUEDのまま | worker適格、空きRAM、予約、通信不明、license poolを読む | QUEUEDを求解中と表示する、broker上限を増やす |
| memory_limit・メモリ高騰 | 停止工程と実使用量を測り、新しい固定版で最小の軽量化を検証する | 32GB機の上限を22GB以上へ上げて通す |
| time_limit・解なし | incumbentの有無と停止理由を記録。必要なケースだけ予算・設定を再検討する | 数学的に運行不可能と断定する |
| Stage 2／Rolling不合格 | 失敗した時間、入力・境界状態、独立物理を追う | Stage 1成功だけで週完了にする |
| CO₂図だけ生成失敗 | 会計・物理・CSVの成立と描画の失敗を分離し、原本から別出力で復旧する | 全求解をやり直す、原FAILEDを消す |
| 会計や物理に不一致 | 原実行計画を再検算し原因を修正。使えない範囲を明示する | 金額を合わせるため電力量・燃料・SOCを変える |

## 同じ試行を照合する順序

1. operationとqueueを特定し、job/attemptを保存記録から読む。
2. 親機のAPIが使える場合は、同じjobとworkerのスナップショットを取得する。別controllerのjobへ操作しない。
3. workerの独立実行記録、attempt別の出力、実行プロセスの対応を確認する。remote PIDを親機のOSで存在確認しない。
4. 応答が不明なら、実行状態も予約も不明として保持する。通信断は「終了」ではない。
5. 終了と原本が確認できたら、既存の `collect` で回収・検算する。再試行が必要でも旧attemptの終了を先に確認する。

キャンセル要求の成功は、実行終了の確認と同義ではない。license解放待ちも考慮する。ライセンス種別・正当なpoolの枠数は実設定で確認し、全PCを同時にEnv起動して試さない。

## メモリ不足は工程別に扱う

Gurobiの使用上限だけでは、PythonのPrepared読込、候補網・モデル構築、結果台帳、回収ZIP、描画の総メモリを保証しない。native solverのmemory_limitとOSのプロセス終了を区別する。

32GB機はおおむね16GiB、64GB機はおおむね32GiBを目安とし、実際の空きRAM・コミット・OS予約・他ジョブを考慮して投入する。週次Gurobiは32GB以上の許可済み端末に限定する。設定上限は実測の最大使用量ではない。親機の管理・回収にも余裕を残す。

改善候補は、入力・固定構造の重複構築の削減、不要Modelの解放、既存の疎な表現、対応済みRolling、threads/profileと予算の配分である。実装と現ログで効果を確認する。便数削減、無根拠な後続候補切捨て、SOC緩和、BESS方策変更で成功させない。

修正版は新しいclean commit・attemptへ適用する。稼働中の固定releaseを編集しない。モデル・入力・費用に影響する修正の場合は、比較できる範囲と再実行対象を明記する。図の修正だけで全12週を再計算しない。

## SOC・日境界・末尾で止まる場合

- 車載BEVとBESSのSOC範囲を分ける。今回BEVは20〜90%、BESSは20〜80%。過去の図やgeneric初期SOCより、対象Preparedの各車両値が正本。
- 帰庫、回送、充電接続、翌朝の最初の出庫とSOC目標の時刻を確認する。0時にSOCをリセットしない。
- 前窓の終了と次窓の開始を照合する。間の時間がある場合は充電・移動・消費を含める。
- 最終翌朝を含む場合、672区間だけで検算を打ち切らない。今回の期待区間はPreparedの追加23/25区間を含む695/697区間。
- 境界参照の保存不具合なら、同じ原状態への対応を検証する。別窓の買電・費用・充放電をコピーして境界を作らない。
- 空のBESSは待機、満杯ならPV抑制。無料補充、系統充電解禁、追加予備・終端復元を修理の代わりに導入しない。

## 図表の警告と本体の不合格を分ける

CO₂係数の図表照合警告が、検算済み原会計を壊していない場合は、注意と図表未完了を表示して結果を保持する。係数・燃料・回送・単位・出典を原本から確認し、別の報告出力へ訂正する。

ただしCO₂の実費用計上や最終会計自体に不整合があれば、単なる描画警告ではない。原本のどこが不一致かを示す。Missing値を0にせず、失敗した判定を成功へ書き換えない。

`recover_weekly_reporting.py` は対応する原ZIP・失敗原因・receiptを検査する既存入口である。すべての失敗を救済する汎用コマンドではない。具体的な引数と適用条件は[結果ガイド](04_RESULTS.md)と `--help` を確認する。

## source/runtimeの照合が止めた場合

SHAだけでなく配置ファイルのdigest、Python・依存、controller設定が一致することを確認する。LF/CRLFやファイル欠落でdigestが違った時も、検査を消して通さない。正規の配布経路で同じ原本を再配置し、配置先を検査する。計算中workerのコードは変更しない。

開発checkoutは現在dirtyで、必要なDBも配置release側にある。開発HEADを計算固定版に見せかけて実行してはいけない。日付付き診断コードや旧SUNNY/RAINのPreparedも、今回の研究入力へ自動転用しない。

## 進捗と通知を誤解しない

入力準備率、受理・待機、確定したRolling時間、検算率、図表率を分ける。求解中の時間経過率やgapを「最適化の完了率」に変換しない。最終翌朝を含む範囲では、営業7日と末尾の両方を示す。

`PENDING_MANUAL_SEND`、EML作成、通知payload作成は送信済みではない。メール送信を依頼された時だけ、送信済み検索とreceiptを照合し、実message IDを保存する。本ガイドの作成・閲覧はメール送信の依頼ではない。

## 修正後に残す記録

原因、対象週・attempt、旧原本hash、変更箇所と実効条件、関連検証、実機で確認した範囲、未確認事項を `DEVELOPMENT_NOTES.md` へ記録する。操作方法が変わる時はREADMEと本ガイドを更新する。研究主張やblockerが変わる場合だけ、対応する研究ノートへ反映する。

人間への確認が必要なのは、実設備の定格・正式fleet承認・利用権限・新しい費用条件等を、既存証拠から確定できない場合である。不明事項と影響を具体化し、無関係な検算・集計は進める。エラーを一件直すたびに、関係のない全機能のレビューからやり直さない。
