# 研究室の計算依頼を受け取る

更新: 2026-09-27。親機の「分散計算」画面から操作します。通常利用にAIは不要です。

## 全端末がどこにあるか

「全端末の所在」から、全台帳と今回の計算用設定を同時に確認できます。
現在、全台帳8868は親機1台＋子機17台、週次計算8891はそのうち5台です。
登録18台が消えたわけではなく、異なる管理サーバーの対象を別々に表示していました。
個々の端末の接続・環境不一致・今回の対象外・割当停止を表で確認できます。

全台帳の接続確認はそのサーバーのコード版との比較です。今回の計算版との一致とは区別します。
同名PCもあり、対応付けにはTailscale IP/host（親機はlocal）を使います。
通信障害中の値は最新とは扱いません。Gurobiは32GB以上かつ利用許可を確認した機器のみ。
台数とソルバーの同時枠は別です。8868から別計算を始めて8891の予約を回避しないでください。

2026-09-27の確認では、8891の2枠はDESKTOP-6AE0MIRとLAPTOP-A709UNA0で使用中。
親機・MATLAB_DESKTOPは新規割当停止、64GB DESKTOP-3PRU7QPは割当無効でした。
64GB機の停止背景には既存のライセンス起動失敗記録があります。これは今回再試験した値ではありません。
端末の設定変更・ライセンス再試験は、既存実行と予約を照合してから行います。

## 依頼を受け取る手順

1. メンバーから、下記テンプレートと入力原本・依存環境の説明を受け取る。
2. 「研究室の計算依頼」→「依頼を作成・取り込む」で、依頼者、テーマ、タスク、
   実行形式、ソルバー、RAM、threads、時間上限、ライセンス利用根拠を記入する。
3. 必要なら入力ファイルを選び、ファイル名・サイズ・SHA256を添付する。本体は転送しない。
   ブラウザーのハッシュ計算は各32MiB・40ファイルまで。大きい原本は別途共有して照合情報を記載する。
4. 「依頼を受付簿へ保存」を押す。親機SQLiteへ保存され、再読込・サービス再起動後も残る。
5. 依頼JSONを保存して受渡し・保管できる。受け取ったJSONの取り込みも同じ受付簿を使う。
   同じID・同じ内容は一度だけ保存し、同じID・異なる内容は拒否する。修正版は新しい依頼として作る。

APIキー、秘密鍵、ライセンスキー、.envはフォーム・依頼JSONへ入れません。
入力原本は承認された研究室内の共有手段で渡し、公開Gitへ追加しません。
受付画面は親機のloopbackのみです。他のメンバーへ親機のネットワークアクセス権を新設していません。
現状はメンバーから受け取った依頼を親機利用者が登録する運用です。

## 受付と実行は別

保存後は必ず `REVIEW_REQUIRED`（実行確認待ち）。この時点でジョブ・attempt・ライセンス予約は作りません。
依頼内にコードやコマンドが書かれていても実行しません。

- この修論モデルのシナリオ: 対象入力を別シナリオとして確認し、既存「実行」画面からPrepare、
  固定版・物理・会計・資源・ライセンスの既存検査を通して投入する。
- 別のPython/他ソルバー: モデル固有の入力・依存・実行入口・結果検査が未確認なので、
  受付だけで自動配布しない。対応ランナーの実装・検証が必要。現時点で任意プログラムの実行サービスではない。
- 利用者・ライセンス: 申告欄は許可の証明ではない。依頼者の利用権とプールを確認する。
  親機利用者の個人資格情報を他のメンバーへ複製・自動適用しない。

今回の実装は受付までです。受付簿を実ジョブに自動連結する機能や、複数利用者向け認証・遠隔ポータルは未実装です。
本番タスクを受け取った時点で、そのモデルに必要な実行対応を絞って進めます。

## 管理者向け設置と保管

既存 `supervisor_ui.py --operation <operation.json>` に受付・結果配信を追加しています。
初回設置は[週次運用手順](weekly_operations.md)の監督サービス登録を使用します。
`controller-settings.queue/controller-supervision/lab-config.json` に管理者が次を指定します。
値は実環境に合わせ、実アドレスや原本パスを公開Gitへ保存しません。

```json
{"inventory_port": 8868, "report_root": "C:/path/to/monthly_report"}
```

`inventory_port` と `report_root` は任意。未設定なら台帳横断・比較結果は表示しません。
受付簿は同じフォルダの `lab-intake/requests.sqlite3`。停止中またはSQLiteバックアップAPIで保管し、
求解キューと混同して消さないでください。受渡しJSONにも依頼者・内容が含まれます。
ブラウザーから設定パスや任意コマンドを指定するAPIはありません。
既存のHost・Origin・セッションnonce検査を使い、別コントローラーからの変更は拒否します。

「月別の結果」では検算済みの表・費用図・CSVを参照できます。ダウンロードはmanifestのhashと計算SHAを照合します。
図表修復した週は元試行の失敗を保持した別集計として表示し、通常の完了件数を書き換えません。
