# 研究室の計算PCを使うAIへの指示書（後輩のPC用）

2026-11-19。後輩のPCで動くAIアシスタントが、研究室の計算PCへ、使用者（後輩本人）のPythonとGurobiのコードを投入するための指示です。
各人のAI設定（CLAUDE.md、AGENTS.md など）にそのまま貼れます。仕組みの全体は [lab_gateway.md](lab_gateway.md)。

> 運用者（劉承洋）から受付口のURLと**個人トークン**を受け取った後にだけ使います。受け取っていなければ、計算の投入はせず、使用者に伝えます。

## 1. 使い方（これ以外の方法で台に触れません）

1. `tools/lab_gateway/lab_client.py`（標準ライブラリのみの1ファイル）を使用者のPCに置きます。
2. 環境変数 `LAB_GATEWAY_URL` と `LAB_GATEWAY_TOKEN` を設定します。トークンはこの環境変数にだけ置きます。
3. 投入、確認、結果の受け取り：

```text
python lab_client.py submit ./project --entry main.py --ram 4 --time 60 --threads 2 --name my-run --key my-run-1
python lab_client.py wait JOB_ID
python lab_client.py fetch JOB_ID --out ./results
python lab_client.py list | status JOB_ID | cancel JOB_ID | pool
```

- `./project` は、実行するコードと小さい入力だけを入れたフォルダです（100 MiB以下）。大きなデータは含めません。
- 実行されるのは `python <entry> <args>` です。`--args` には英数字と `_ . / = : , -` だけを渡せます。
- 結果は環境変数 `MC_LAB_OUTPUT_DIR` のフォルダへ書くようにコードを作ります。そのフォルダと標準出力・標準エラーが返ります。
- 使えるのは台のPython環境（gurobipy、numpy、pandas、scipy、pydantic）です。ほかのパッケージの導入はできません。コードがそれ以外を要るときは、使用者に伝えます。

## 2. 台の割当とリソース

- 台を指名しません。親機が、プールの中の空いていて条件を満たす台を選びます。空きがなければ待ちます。
- `--ram`（必要な GiB）と `--time`（時間上限、分）は、実際に必要な値を書きます。短くしたり小さくしたりして順番を早めません。
  RAMがどの台の上限も超えると `REJECTED` になります。台の上限（搭載−8 GiB）は小さい台で約4 GiBです。
- 時間上限で止められます（`TIMEOUT`）。途中から再開する機能はないので、長い計算は小さい独立したタスクに分けます。
- 台のPCが落ちる・スリープする・つながらなくなると `LOST` になります。自動では再実行されません。

## 3. ライセンス

- Gurobiは、各台に用意された、その台のライセンスだけを使います。
- ライセンスファイル、キー、`GRB_LICENSE_FILE` などの環境変数に、触れません（読む・書く・複写・投入物への同梱）。
- コードの中で別のライセンスを指定しません。ライセンスのエラーが出たら、繰り返し投入せず、エラー内容を使用者へ報告します。

## 4. してはいけないこと

- ゲートウェイ以外の経路（台へのSSH、親機の管理画面・内部API）に接続すること。PC・ネットワークの設定（SSH鍵、Tailscale、ファイアウォール、電源など）を変えること。
- トークンを、ファイル、ログ、成果物、共有物、公開リポジトリへ書くこと。他の人へ渡すこと。
- 他の人のタスクを見る・止める操作（できないようになっていますが、試みません）。
- 失敗したとき、条件（入力、パラメータ、時間上限、メモリ）を黙って変えて再投入すること。
- 投入の制限（件数・サイズ・頻度）を回避すること。通信が切れたときは、二重に投入せず、`list` で投入済みかを確かめます（再投入するときは同じ `--key` を使うと同じタスクが返ります）。
- 修論モデルの固定版・時刻表・入力データを、後輩のコードの中で書き換えること。

## 5. 結果の扱い

- `COMPLETED` は「プログラムが終了コード0で終わった」だけを意味します。結果が正しい、最適である、研究結論に使える、という意味ではありません。
  Gurobiの状態（最適・時間切れ・実行不能など）と、研究で必要な検査の結果を、そのまま報告します。
- `FAILED`・`TIMEOUT`・`CANCELLED`・`LOST`・`REJECTED` は、タスクID、状態、メッセージ、台の名前を省略せず使用者へ伝えます。

## 6. 迷ったとき

- 存在を確認できていない機能や項目を、推測で使いません。`lab_client.py --help` と [lab_gateway.md](lab_gateway.md) を読み、なお不明なら使用者に聞きます。
- 台・ライセンス・優先順位に関わる判断は、使用者を経由して劉承洋へ確認します。
